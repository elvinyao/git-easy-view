# ユーザーガイド

[ドキュメント一覧](../README.md) · [简体中文](../zh-CN/user-guide.md) · [English](../en/user-guide.md)

## 1. アプリケーションの目的

Git Easy View は、複数の GitHub / GitLab リポジトリについて、ブランチ、最新コミット、PR/MR の関係を 1 つのプロジェクト画面にまとめます。十数個のリポジトリの main / master、release、feature を日々確認するためのツールです。

プラットフォーム API と HTTPS Git を読み取ります。checkout、merge、push、リモートブランチ削除は行いません。画面にはバックグラウンド同期で取得したローカルスナップショットを表示します。

## 2. アクセス、権限、言語

ローカルの標準 URL は [http://127.0.0.1:8766](http://127.0.0.1:8766) です。本番 URL は運用担当者が案内します。

| 利用者 | 操作できる内容 |
|---|---|
| 未ログイン | 全プロジェクト、関連付けられたリポジトリ、ブランチ、コミット、関係、PR/MR 履歴の閲覧 |
| 一般アカウント | 未ログインと同じ閲覧機能 |
| 管理者 | 閲覧に加え、プロジェクト、アカウント、トークン、リポジトリ設定、同期・比較ジョブの管理 |

プロジェクトのメンバー設定や「管理者専用」などの名前は、閲覧を制限しません。どのプロジェクトにも関連付けられていないリポジトリは管理者だけが閲覧できます。関連付けたリポジトリのスナップショットは匿名で閲覧できるため、管理者はインポート前に公開範囲を確認してください。

言語設定は `/login` にあります。中文、日本語、English を選び、そのままプロジェクト一覧へ戻れます。ログインは不要です。ブラウザーは選択を保存し、他の画面には言語切り替えを表示しません。優先順位は URL の `lang`、言語 cookie、ブラウザーの言語、既定の中国語です。リポジトリ名、ブランチ名、コミットメッセージ、PR/MR タイトルは原文のまま、時刻は UTC で表示します。

## 3. プロジェクト全体のブランチを確認する

トップページからプロジェクト（例：`/projects/1`）を開きます。リポジトリごとに次を表示します。

- デフォルトブランチの最新コミット：ブランチ名、UTC 時刻、短い hash、message の先頭行。
- 現在存在する全ブランチ：主幹、release、feature、その他のグループ。
- デフォルトブランチとの関係、ahead / behind のコミット数。
- Git / API 同期時刻、ジョブ状態、期限超過や接続停止の表示。

プラットフォームが指定したデフォルトブランチを優先し、見つからない場合は `main`、`master` の順に探します。他のブランチは最新コミット順で、アクティブな release を優先します。アクティブ指定がなくても release は表示されます。

まず上部の**リポジトリ概要表**で、デフォルトブランチ、現在または最新の release、最新の feature、Git / API それぞれの同期状態を横並びで比較します。概要はリポジトリ全体の最新状態を維持し、ブランチの絞り込みは下部の一覧に適用します。件数リンクはブランチの絞り込みを解除し、該当グループの全件へ移動します。release の状態はコミットの状態であり、環境へのデプロイ状態ではありません。

1 ページは最大 50 リポジトリです。リポジトリ名とブランチ名を別々に検索し、役割・関係・同期の要確認状態で絞り込めます。デフォルトブランチは比較用に残り、一致件数と全件数を区別します。下部の**全ブランチ一覧**は通常すべて展開されます。「すべて折り畳む」で閉じ、見出しや概要のリンクで必要な一覧を開けます。一覧内の小さなスクロール領域はありません。条件やページは URL に保存されます。削除済みブランチは表示しません。

ブランチ名や hash をクリックすると**詳細サイドパネル**が開き、プロジェクト画面のまま名前、コミットタイトル、作者、hash、変更ファイル、比較対象、PR/MR の証拠を確認できます。Esc または閉じるボタンで元の位置に戻ります。戻る・進む・再読み込みで選択を復元できます。完全な履歴は下部の Git ワークスペースへのリンクから開き、「プロジェクトに戻る」で条件を維持して戻れます。時刻は相対表示で、ホバーすると UTC の日時を確認できます。詳細関係表のページ分割は全ブランチの件数に影響しません。

## 4. ブランチ関係の読み方

関係は画面に示す現在の source OID と target OID に対する結果です。プロジェクト概要ではデフォルトブランチが target です。詳細画面では別の明示的な target を利用できます。

| 状態 | 意味 | 例 |
|---|---|---|
| 同一 | 両ブランチが同じコミットを指す | `feature/a` と `main` の hash が同じ |
| コミットを包含 | source の現在のコミットへ target の履歴から到達できる | feature に独自コミットがなく、target は先へ進んでいてよい |
| すべてのコミットは含まれていません | target にない source のコミットがある | `ahead=3, behind=0` は 3 件先行、`ahead=3, behind=2` は双方が分岐 |
| 共通履歴なし | 現在のコミットグラフに共通祖先がない | 通常の先行／遅れとして扱わない |
| 未解析 / 結果なし | 固定コミット間の比較キャッシュが利用できない | 同期を待つか管理者に比較を依頼 |

証拠は次の 3 種類を分けて読んでください。

1. **派生元候補**：共通祖先からの推定、または管理者の宣言。Git はブランチの作成元を永久には記録しません。
2. **予定ターゲット**：オープン PR/MR や手動設定による予定です。
3. **現在の包含関係と過去のマージ記録**：前者は現在の到達可能性、後者はプラットフォームの過去イベントです。force push、追加コミット、squash / rebase merge などで異なる結果になります。

例えば、PR のマージ後に feature に 2 コミット追加すると `ahead=2` になり得ます。過去の PR/MR が見つからなくても「一度もマージされていない」とは断定できません。履歴の対象期間を確認してください。cherry-pick、revert、squash の内容等価性は判定しません。

プロジェクトから詳細、ワークスペース、証拠画面へ進んでも、比較対象はデフォルトブランチを維持します。「main との比較」など対象を明記し、手動の予定ターゲットは別に表示します。未包含のコミットがあることは通常の開発状態で、同期失敗ではありません。

## 5. Git ワークスペースとコミット詳細

`/repositories/{id}/branches` は IDEA Git Log に似た 3 ペインです。

1. 左：ブランチを検索・選択し、役割別に確認。
2. 中央：実際のコミットトポロジーと履歴からコミットを選択。
3. 右：完全な hash、作者、message、変更ファイル、ブランチ関係を確認。

ブランチ選択で履歴が絞られ、コミット選択で詳細が更新されます。選択・絞り込み・ページは URL に保存され、戻る、再読み込み、共有に対応します。

履歴は最大 100 コミット、ファイル一覧は最大 200 件です。マージコミットの変更は最初の親コミットと比較します。ローカル Git オブジェクトだけを読み、閲覧ではリモート同期を開始しません。サンプルの 3 コミットは空ツリーなので変更ファイルがありません。実リポジトリでは実際のパスと変更状態を表示します。

## 6. PR/MR とデータの鮮度

リポジトリ画面とブランチ詳細に PR/MR とプラットフォームへのリンクがあります。通常は全オープン記録と、過去 90 日以内に更新された closed / merged 記録を取得します。増分同期でより古い記録が残ることもあり、管理者は履歴の開始日を指定して補完できます。

コミット時刻はコードのコミット日時、Git 同期時刻はブランチ取得日時、API 同期時刻は PR/MR 取得日時です。別々に確認してください。Git と API の期限超過判定は独立しており、同期間隔の 2 倍、最低 60 秒をしきい値とします。

キャッシュ表示の更新は保存済みデータを読み直します。管理者の即時同期だけがリモート取得ジョブを作ります。失敗や接続停止時も旧スナップショットを閲覧できるので、状態表示を併せて確認してください。

インポートや手動同期後は、リポジトリごとに待機・実行中・完了・失敗を表示します。成功時にスナップショットを更新し、失敗を完了扱いにはしません。状態取得の失敗は再試行でき、長時間ジョブは自動確認停止後も手動で更新できます。初回同期待ち、初回失敗、空リポジトリ、絞り込み結果なしを区別し、同期中も以前のデータを表示します。

## 7. 管理者の初期設定

インストールだけではアカウントを作りません。運用担当者が[デプロイガイド](docker-deployment.md#3-管理者と任意のサンプルデータ)に従って管理者を作り、`/login` でログインします。

1. `/admin` でプロジェクト名、一意の slug、説明を登録。
2. GitHub / GitLab 接続を作成し、HTTPS インスタンス URL、token、必要なら社内 CA のコンテナ内パスを入力。
3. 保存後に接続を確認。資格情報や CA の変更後は停止状態となり、確認成功で再開。
4. 名前や名前空間で検索し、対象プロジェクトと 1–50 件のリポジトリを選択。ページ単位で選択し、ページを移動しても選択を保持します。インポート済みの表示と選択件数を確認して送信。初回同期の進捗はプロジェクト画面で確認します。
5. 同期間隔、release / feature の接頭辞、アクティブ release を設定。
6. 必要に応じて派生元の宣言、予定ターゲット、主な比較対象、PR/MR 履歴補完を設定。

同じリポジトリを複数プロジェクトへ関連付けると、キャッシュ・解析結果を共用します。既存リポジトリの接続を別のプラットフォームやインスタンスへ変更できません。新しい接続を作ってください。アカウント管理では作成、パスワード再設定、有効・無効、管理者権限を変更できます。Web フォームのパスワードは 12–1024 文字です。現在の管理者は自分を無効化したり、管理者権限を外したりできません。

token は暗号化保存され、以前の値は再表示されません。権限と CA の詳細は[Docker・自動デプロイ](docker-deployment.md#5-プラットフォーム-token-と社内-ca)を参照してください。

入力エラーは元のフォームに表示され、機密情報以外の入力は保持されます。該当項目を修正し、パスワードや token は再入力してください。管理画面へのログイン後は元の操作先へ戻ります。モバイルでもアカウント表示とログアウトを利用できます。

## 8. よくある質問

| 状況 | 対応 |
|---|---|
| プロジェクトがない | 新規インスタンスは空。管理者がプロジェクトとリポジトリを登録 |
| ブランチが見つからない | 絞り込みを解除し、対象リポジトリを展開。ページと Git 同期を確認。削除済みは表示されない |
| hash はあるが message がない | オブジェクト不足やキャッシュ使用中。再読み込みし、継続する場合は管理者へ |
| 最新コミットが出ない | 表示更新では取得しない。定期同期を待つか管理者に即時同期を依頼 |
| マージ済みなのに独自コミットあり | 現在の OID、target、追加コミット、履歴書き換えを確認 |
| 管理画面がない / 403 | 管理者アカウントでログイン。一般アカウントは閲覧のみ |
| 匿名のリポジトリ URL が 404 | 存在しないかプロジェクトとの関連付けがない |
| 本番ログイン後にログイン画面へ戻る | HTTPS、プロキシ、Secure cookie、安定した session secret を確認 |

問い合わせには URL、リポジトリ／ブランチ名、時刻、短い hash、スクリーンショットを添えてください。token、パスワード、env ファイル、セッション cookie は添付しないでください。
