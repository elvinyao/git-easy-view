# 发布管理易用性改进

## 目标和边界

根据用户对上一版“太不友好”的反馈，在已经确认的“仓库摘要＋完整分支列表＋详情侧栏”架构内改进完整发布体验。沿用单容器、匿名查看、管理员修改、中日英，以及实际上线和主干合并分别确认的规则。此工作继续修改当前包含未提交功能的工作区，不丢弃已有改动，不创建示例生产记录。

## 当前证据

- 创建入口未选择仓库时一次显示所有仓库的完整字段，没有选择计数和定位。
- 分支和 Tag 使用原生 datalist，外观像自由文本，移动端不明确；目标主干、MR 和核心字段同等突出。
- 保存草稿后还要再次打开详情启动，缺少提交前确认和未完成原因。
- 用户必须先打开详情、找到表单才能确认上线；三个仓库占据整排大卡片，十几个仓库难比较。
- 本番登记与 MR 配置混在长页中，要求用户查平台数字 ID。
- 无效字段跳到独立错误页，之前输入没有服务端恢复。

## 方案比较

只调整颜色和间距无法解决选择和操作负担；单页展开所有表单仍不适合 42 个仓库。采用渐进展示：向导负责创建，紧凑表格负责日常检查，侧栏负责有上下文的确认。

## 交互规格

1. 创建三步向导。第一步只显示可搜索的仓库列表、当前本番/分支数量和已选计数；支持选中当前筛选结果、清空，最多 50 个。已从概览选好仓库则进入版本步骤，但可以返回增加或删除仓库。
2. 第二步仅展示选中仓库。分支、Tag 为带搜索的原生 select；选择后的预览显示短 hash、提交摘要和时间。主干默认填入，MR 和目标放在“更多设置”。未选 tag 明确提示可保存草稿。不会猜测或自动提交生产状态。
3. 第三步显示日期、名称、各仓库固定版本和待处理项。可以创建并启动，或保存草稿。没有 tag 时启动按钮说明原因并禁用。返回修改不丢内容；后端仍严格校验，不依赖 JS 验证。
4. 发布列表区分发布计划和本番概览，给出计划/待上线/本番登记的可读摘要与空状态行动。仓库支持搜索，用户不需要浏览 42 行空记录才能理解入口。
5. 计划详情用每仓库一行的表格，显示计划版本、实际上线状态、主干合并状态以及明确下一步。顶部显示完成数。行操作直接打开相应侧栏表单并聚焦；只读用户能查看相同状态与证据。
6. 本番登记重点展示当前版本和待登记版本。历史、回滚和可选 MR 配置分组折叠；回滚和人工合入仍要求依据。
7. 本地 MR 绑定提供平台仓库名称搜索/选择。列表仅在管理员点击读取时访问平台；保留数字 ID 作为高级备用输入。请求失败显示重试且保留表单。
8. 字段错误在原表单内定位，保留名称、日期、仓库选择、分支、tag、MR、备注。失效版本不得悄悄改为最新值；提示刷新/重新选择。CSRF、权限、外部 URL 和版本冲突验证保持有效。

## 数据与实现

复用 ReleasePlan/ReleaseItem/Deployment，没有新数据库表。向导使用服务器渲染的数据和少量渐进增强脚本。无 JS 时仍可填写单页并提交；业务校验只在服务器执行。新增表单上下文/恢复帮助模块，避免继续扩大路由。平台仓库列表使用已有 provider 和凭据/CA 校验。

## 验收证据

- 在 42 仓库页面可搜索并选 3 个，创建时只处理这 3 个；返回更改选择不丢输入。
- 中日英真实浏览器完成创建、保存草稿、启动、上线和人工合入；部分完成不误标全部完成。
- 字段错、tag 移动、无 tag、无 MR 连接、API 失败和过期页面都有明确操作路径。
- 390px 手机和 1440px 桌面截图无横向溢出，键盘可使用选择器、步骤和 dialog。
- 未登录只读、成员拒绝写入、CSRF 和并发检查均回归通过。
- 部署后实际项目 3 可用，继续一个运行容器，无宿主依赖安装。

## 自审

本轮不改变发布完成条件、不自动部署、不新增标签、不重新整理其他功能。向导顺序和选择范围明确；服务端保留值优先于默认值。测试必须覆盖流程质量，不能只以页面返回 200 作为可用性证据。
