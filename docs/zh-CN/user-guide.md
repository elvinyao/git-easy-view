## 发布计划与本番版本

项目页的「发布管理」可匿名查看；所有修改需要管理员。「发布计划」页签显示草稿、进行中和已完成的计划；「本番概览」是独立页签，可搜索仓库，查看实际运行版本或登记尚未记录的本番。

在单页表单中创建 RLS 计划：

1. **计划信息**：填写计划名称、日本时间的计划日期和可选备注。
2. **选择仓库**：搜索名称或命名空间，勾选 1–50 个仓库。可选择筛选结果、清空选择，并查看已选数量；也可从项目摘要勾选仓库后直接进入创建页。
3. **选择版本与启动**：勾选仓库后，页面下方即时展开对应仓库的版本设置。搜索并选择实际分支和 Tag，核对短 hash、提交摘要和时间；「更多设置」中可调整默认主干合并目标、关联 MR。Tag 从 Git 同步，支持普通 Tag 和指向 commit 的 annotated tag，非 commit Tag 不用于发布。Tag 尚未准备好时可先点击「保存草稿」；全部所选仓库版本就绪后可点击「保存并启动计划」，启动后固定所有版本，不能编辑。

提交出错时，原表单保留名称、日期、选择、MR 和备注，并在对应字段显示错误；分支或 Tag 失效时需重新选择，不会自动改为最新版本。

计划详情按仓库逐行显示计划版本、上线状态、主干合入状态和「下一步」，顶部显示各项完成数。实际部署后，点击该行「确认上线」会直接打开侧栏的上线表单；勾选固定版本已在本番运行，即可更新此项目的本番记录。可展开调整上线时间或添加备注。随后点击「核对合入」，关联具体 MR 等待同步核验，或填写必填的合入依据人工确认。只读用户可通过「详情」查看相同状态和证据。只有上线和合入都已确认才完成该仓库，全部仓库完成才完成计划；超过计划日期仍未完成会提示。取消计划保留已上线历史，不撤销部署。

当前本番按项目和仓库分别保存。在「本番概览」点击「登记本番」，选择已实际运行的分支及可选 Tag，核对待登记版本后保存。初次登记的备注为可选；实际时间留空表示现在。历史与回滚放在「本番历史」折叠区：选择旧记录，填写必填的回滚依据，记录已经实施的回滚；系统新增记录并保留原始历史。系统记录发布事实，不执行部署、回滚、创建 Tag 或合并 MR。分支继续提交、Tag 移动/删除都不会改变已固定版本；有变化会提示。

本地仓库可展开可选的「自动核验 MR」，选择已验证的只读 GitLab/GitHub 连接，点击「读取仓库列表」，再按名称搜索并选择平台仓库，最后「验证并绑定」。找不到仓库时可在「高级：使用仓库 ID」填写 GitLab 项目数字 ID 或 GitHub 仓库数字 ID；读取失败时可重试，当前选择会保留。只有管理员主动读取列表时才请求平台，普通页面浏览不会触发请求。代码继续来自本地目录，绑定只获取 MR 元数据，对所有使用该仓库的项目生效；远程仓库使用原平台连接。MR 状态通过后台同步更新，未绑定平台时仍可填写依据人工确认合入。

自动确认要求关联具体 MR，仓库身份、来源分支、目标分支、来源 SHA 与计划固定 SHA 全部一致，并有平台合并时间。Squash 合并可由平台记录确认。SHA 不同、API 失败/过期、未绑定平台或记录缺失时不会自动完成；可同步后重试，或填写合入依据人工确认。迟到的 MR 不会覆盖较新的本番版本。计划日期和上线输入使用 Asia/Tokyo；历史时间显示 UTC。

## 1. 这是什么

Git Easy View 把多个 GitHub / GitLab 或本地 Git 仓库的分支、最新提交放在同一个项目仪表盘中，并为远程来源展示 PR/MR 关系。适合每日检查十几个仓库的主干、release 和 feature 状态。

应用读取平台 API、HTTPS Git 或只读挂载的本地仓库，不执行 checkout、merge、push 或远端分支删除。页面内容来自后台同步后的本地快照。

## 2. 访问、权限与语言

默认本地地址为 [http://127.0.0.1:8766](http://127.0.0.1:8766)。生产地址由运维提供。首次部署不自动创建任何账号；本地演示执行 `seed-local.py` 后创建管理员 `demo-admin` 与普通账号 `demo-member`（密码保存在本地 `runtime/demo-access.json`），或通过 `app.cli create-user --username admin --admin` 自建管理员（详见 [文档目录](../README.md)）。

| 身份 | 可以做什么 |
|---|---|
| 匿名访问者 | 查看全部项目、项目关联仓库、分支、提交、关系与 PR/MR 历史 |
| 普通账号 | 与匿名访问者相同的只读功能 |
| 管理员 | 以上功能，以及管理项目、账号、平台令牌、仓库配置、同步和比较任务 |

项目成员配置及“管理员专属”等项目名称不限制项目读取。未关联任何项目的仓库只对管理员可读。把仓库关联到项目后，该仓库的快照即可匿名查看；展示范围应由管理员在导入前确认。

语言只在 `/login` 登录页面设置，可选中文、日本語、English。选择后可以直接返回项目列表，无需登录；浏览器会记住选择。其他页面不显示语言切换。优先级为 URL 的 `lang`、语言 cookie、浏览器语言、默认中文。仓库名、分支名、message 和 PR/MR 标题保留原文；时间按 UTC 显示。

## 3. 项目总览：一次查看整个项目

从首页选择项目，例如 `/projects/1`。每个仓库显示以下内容：

- 默认主干最新提交：分支名、UTC 时间、短 hash、message 首行。
- 所有当前分支：按主干、release、feature、其他角色分组，不只展示最近一条。
- 相对默认主干的状态、领先（ahead）与落后（behind）数量。
- Git / API 同步时间、任务状态、过期或连接暂停提示。

默认主干优先使用平台声明的分支；找不到时依次尝试 `main`、`master`。其他分支按最近提交排序，活跃 release 优先。管理员未标记活跃 release 时，release 仍会显示。

先看顶部**仓库摘要表**：每行一个仓库，横向比较默认主干、当前或最近 release、最新 feature，以及分别标明的 Git / API 同步状态。摘要保留整个仓库的最新状态，分支筛选只影响下方列表。数字链接会清除分支筛选并定位到完整分支组。摘要中的 release 状态是分支提交状态，不代表已部署到某个环境。

每页最多 50 个仓库，仓库导航可快速定位。仓库名称与分支名称分开搜索，也可按角色、关系及“仅看同步需关注”筛选。默认主干保留作比较上下文，数量区分匹配数与全部分支数。下方**完整分支列表**默认全部展开；“全部收起”折叠仓库列表，点击仓库标题或摘要链接即可展开，无需在小区域内反复滚动。筛选与分页保存在 URL，可刷新或分享。总览不列已删除分支。

点击分支名或 hash 打开**详情侧栏**，留在项目页查看完整名称、提交标题、作者、hash、变更文件、比较对象及 PR/MR 证据。Esc 或关闭按钮返回原位置；浏览器前进、后退及刷新可恢复选择。需要完整履历时使用侧栏底部的 Git 工作区链接，再通过“返回项目”保留原筛选。时间默认显示相对时间，悬停可查看完整 UTC 时间。“详细关系表”仍可按需展开，其分页不会减少完整列表的分支数。

## 4. 如何读懂分支关系

关系针对页面注明的当前源 OID 和目标 OID。项目总览的目标是默认主干；分支详情可使用其他明确目标。

| 状态 | 含义 | 例子 |
|---|---|---|
| 相同 | 两个分支指向同一个提交 | `feature/a` 与 `main` 的 hash 相同 |
| 提交已包含 | 源分支当前提交可从目标历史到达 | feature 无独有提交，目标可以继续前进 |
| 未全部包含 | 源分支有目标尚未包含的提交 | `ahead=3, behind=0`：领先 3；`ahead=3, behind=2`：双方已分叉 |
| 无共同历史 | 当前提交图中没有共同祖先 | 不能直接解释为普通领先／落后 |
| 未分析 / 无结果 | 对应固定提交的缓存比较尚不可用 | 等待同步，或联系管理员安排比较 |

三类证据要分别阅读：

1. **来源候选**：根据共同祖先推断，或管理员人工声明。Git 没有永久保存“从哪个分支创建”的记录。
2. **计划目标**：开放 PR/MR 或人工配置中的目标，表示意图。
3. **当前包含关系 / 历史合并记录**：前者是当前 Git 可达性，后者是平台发生过的事件。force push、后续提交、squash / rebase merge 等会使两者不同。

例如，PR 已合并，但 feature 随后新增两个提交，当前仍可以显示 `ahead=2`。没有历史 PR/MR 记录也不能证明从未合并；检查页面注明的覆盖时间。应用不判断 cherry-pick、revert 或 squash 后的内容等价性。

从项目页进入侧栏、工作区或证据页面时，继续使用项目的默认主干作为比较对象。页面会明确写出“相对 main”等基准；人工计划目标单独展示，不会悄悄替换当前比较对象。分支未全部包含是正常开发关系，不等于同步失败。

## 5. Git 工作台与提交详情

打开 `/repositories/{id}/branches`，使用类似 IDEA Git Log 的三栏界面：

1. 左侧搜索并选择分支，可按角色分组。
2. 中间查看真实提交拓扑和履历，点击一条提交。
3. 右侧查看完整 hash、作者、message、变更文件及分支关系。

选中分支后历史随之筛选；选中提交后详情更新。选择、筛选与分页保存在 URL，支持返回、刷新和分享。

履历最多读取 100 条提交，文件列表最多 200 项；合并提交的文件变化相对第一个父提交计算。工作台只读本地 Git 对象，打开页面不会发起远端同步。示例仓库的三个提交使用空文件树，因此没有变更文件；真实仓库显示真实路径和变更状态。

## 6. PR/MR 与数据新鲜度

仓库页和分支详情提供 PR/MR 信息及平台链接。默认读取全部开放记录，以及最近 90 天内更新的关闭／合并记录；增量同步可能保留更早记录，管理员也可指定历史起始日期补录。

提交时间表示代码提交的时间；Git 同步时间表示分支快照获取时间；API 同步时间表示 PR/MR 获取时间。它们不应混为一谈。Git 和 API 分别判断过期，阈值为同步间隔两倍且不少于 60 秒。

“刷新缓存视图”重新读取已有数据。管理员的“立即同步”才安排后台读取远端。某次失败或连接暂停时，旧快照仍可浏览，但应结合状态提示判断。

导入或手动同步后，进度区按仓库显示排队、执行、完成或失败。成功后更新快照，失败不会冒充完成。状态读取失败可重试；长任务停止自动轮询后可继续“刷新状态”。首次同步等待、首次失败、空仓库和筛选无结果有不同提示，旧快照在同步期间仍可查看。

## 7. 管理员首次配置流程

安装默认不创建账号。运维先用[部署指南](docker-deployment.md#3-创建管理员与可选示例)创建管理员，再访问 `/login`。

1. 在 `/admin` 创建项目，填写名称、唯一 slug 和描述。
2. 新建 GitHub 或 GitLab 连接，填写 HTTPS 实例地址、token，以及可选的公司 CA 容器路径。
3. 保存后执行连接检查。凭据或 CA 变更会暂停连接，检查成功后才恢复。
4. 进入仓库列表，搜索名称或命名空间，选择目标项目，一次导入 1–50 个仓库。可选择当前页并跨页保留选择，已导入仓库有标记；确认所选数量后提交。首次同步异步执行，在项目页查看各仓库进度。
5. 根据团队规则调整同步间隔、release / feature 前缀，并明确标记活跃 release。
6. 必要时配置分支的人工来源、计划目标和主比较对象，或补录 PR/MR 历史。

同一仓库可以关联多个项目，缓存与分析结果复用。已有仓库的连接不能改成另一平台或实例；请创建新连接。账号管理支持创建、重设密码、启停及管理员权限；Web 表单密码长度为 12–1024 字符。当前管理员不能停用自己或取消自己的管理员权限。

平台 token 由管理员保管，应用加密保存；页面不会回显旧 token。具体权限和公司 CA 设置见[Docker 与自动部署](docker-deployment.md#5-平台令牌与公司-ca)。

表单校验失败会在原页面显示错误并保留非敏感输入，修正对应字段后再次提交；密码和 token 必须重新填写。登录管理页后会返回原操作入口，手机也可查看当前账号并退出。

### 7.1 批量添加本地 Git 仓库

不连接 GitHub / GitLab 时，先按[部署指南](docker-deployment.md#61-本地仓库目录映射)挂载服务器上的仓库根目录。例如 `/Users/elvinyao/workspace` 在页面中对应 `/data/local-git`。

1. 在 `/admin/connections/new` 将“仓库来源”选为“本地 Git 目录”，填写来源名称。
2. 点击“选择目录…”，进入需要的子目录并点击“使用此目录”。也可直接填写挂载范围内的容器路径。
3. 点击“保存目录并扫描仓库”。应用递归发现普通仓库和裸仓库；发现仓库后不再进入其工作区，隐藏目录及依赖目录会跳过。
4. 选择目标项目，勾选仓库，点击“导入选中仓库”。每次最多 50 个，支持跨页选择；随后在项目页查看同步进度和完整分支概览。

本地来源不需要 token，不连接远程平台。只读本地 `refs/heads` 分支及已提交历史，不包含 remote-tracking 分支和未提交改动；默认主干优先 `main`、`master`，然后当前 HEAD。API 和 PR/MR 显示“不适用”。定时或手动同步重新读取本地目录，分析副本写入独立缓存，原仓库保持只读。

目录选择针对运行应用的服务器；部署到内网后不能直接浏览访客电脑的磁盘。扫描最多 1,000 个仓库、5,000 个目录、12 层；达到上限或部分目录不可读时，页面明确提示“部分目录未扫描”。可导入已找到的仓库，再选择更小的目录补充扫描。linked worktree 的 Git 元数据也必须位于挂载范围内，且其中路径在容器内有效。导入后保持目录映射稳定；移动仓库或换根目录时创建新来源。

## 8. 常见问题

| 现象 | 处理 |
|---|---|
| 首页没有项目 | 新实例是空的，管理员需要创建项目并导入仓库 |
| 找不到某个分支 | 清除搜索和筛选，展开对应仓库并检查分页及最近 Git 同步；已删除分支不在总览 |
| hash 有了但 message 暂不可用 | 本地对象缺失或缓存正忙，稍后刷新；持续出现时联系管理员同步 |
| 最新提交未出现 | 刷新视图不会抓取远端；等待定时同步或请管理员立即同步 |
| 已合并 PR，但显示独有提交 | 对照当前 OID、比较目标与历史合并证据，可能有后续提交或历史改写 |
| 管理入口不见了 / 返回 403 | 使用管理员账号登录，普通账号只有只读权限 |
| 匿名仓库 URL 返回 404 | 仓库不存在，或尚未关联项目；请管理员确认 |
| 生产环境登录后又回到登录页 | 必须通过 HTTPS 访问；检查反向代理、Secure cookie 和稳定 session secret |

故障反馈提供页面 URL、仓库／分支名、时间、短 hash 和截图。不要附带 token、密码、env 文件或会话 cookie。
